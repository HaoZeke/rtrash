#+title: Architecture and safety model
#+options: toc:2 num:nil

* What rtrash is

A *native* FreeDesktop trash implementation: one Rust library driving the =rtrash= multi-call CLI and optional Python bindings.
Files are *moved* into the same trash layout used by GNOME/KDE/Xfce file managers, not unlinked.

* FreeDesktop layout

| Location | Role |
|----------------------------------+----------------------------------------|
| =$XDG_DATA_HOME/Trash= | Home trash (default =~/.local/share/Trash=) |
| =$top/.Trash/$uid= | Per-mount shared trash (sticky, non-symlink) |
| =$top/.Trash-$uid= | Per-mount private trash |
| =files/= + =info/*.trashinfo= | Payload + =Path= / =DeletionDate= metadata |

Atomic reservation: create-new on =.trashinfo= *before* moving the payload (spec requirement).
Collisions become =name.2=, =name.3=, …

* Platform backends

| OS | Backend |
|----+---------|
| Linux | Full FreeDesktop (home + volume trash) |
| macOS (experimental) | FreeDesktop *home* trash only — *not* Finder Trash |
| Windows | System *Recycle Bin* (shell APIs) — *not* FreeDesktop on-disk layout |

Linux remains the primary multi-call / musl-release niche.

* Safer than permanent delete (=os.remove= / =rm= without trash)

| Risk | =os.remove= / =Path.unlink= / =rm= | rtrash put |
|----------------------------------+------------------------------------|----------------------------------|
| Data gone immediately | Yes | No — recoverable until empty |
| Shared with DE trash UI | No | Yes (FreeDesktop) |
| Accidental =rm -rf= of work tree | Permanent | Recover with =restore= |
| Cross-device | Unlink only | Copy-into-home-trash fallback |

rtrash put also applies *rm-shaped fail-safes*: refuse =.= / =..= / =/= (with preserve-root), require =-r= for directories, GNU-style last-wins for =-f= / =-i= / =-I=, exit codes 0/1/2.

* Safer than a naive “mv to ~/. Trash” script

- Correct =.trashinfo= encoding (percent-encoded =Path=)
- Mount-aware placement (not only home trash)
- Concurrent-safe name allocation
- Restore overwrite protection (=-f= to replace)
- Empty with age filter, dry-run, orphan purge (any empty, including age filter), =directorysizes= prune
- List surfaces =files/= names with no =.trashinfo= as emergency =ORPHAN= rows; restore refuses them

* Versus Python trash-cli (design, not speed)

| Axis | trash-cli | rtrash |
|----------------------------------+---------------------------|--------------------------------|
| Runtime | CPython suite of scripts | Single native binary / lib |
| FreeDesktop put/list/empty/restore/rm | Yes | Yes (multi-call + subcommands) |
| rm-compatible put flags | Partial (own CLI) | Strong (GNU-style set) |
| Permanent =os.remove= replacement API | Separate process spawn | In-process Python module |
| Parallel full empty | Sequential Python | Rayon + bulk unlinkat; btrfs subvol ioctl when applicable; optional MPI =drm= |

* Permanent-delete backends

=rm=, =empty=, and the empty TUI purge payloads directly under a trash =files/= directory through one helper (=trashdir::remove_trash_payload=).

| Backend | Chosen when | Module |
|---------+-------------+--------|
| btrfs subvolume destroy | payload is a btrfs subvolume root (ino 256) | =fastdelete.rs= |
| mpifileutils =drm= | =drm= + =mpirun= / =mpiexec= / =srun= on =PATH=; =RTRASH_DRM=always=, or =auto= with a parallel/network filesystem (Lustre, GPFS, BeeGFS, NFS, SMB, CephFS, PanFS, OrangeFS) at =RTRASH_DRM_MIN_ENTRIES=, or a local one at =RTRASH_DRM_LOCAL_MIN_ENTRIES= | =drm.rs= |
| rayon + =unlinkat= | everything else, and any drm failure | =fastdelete.rs= |

drm is spawned as =LAUNCHER -np N drm -- PATH= from an argv vector. =PATH= is the canonical path of a real (non-symlink) directory whose parent is the resolved =files/=; user paths, restore destinations, and symlink targets never reach it. The =.trashinfo= is unlinked only after drm exits 0 and the path is gone; otherwise the exit status is reported and the native walker runs. =[drm]= in =$XDG_CONFIG_HOME/rtrash/config.toml= holds the same settings as the =RTRASH_DRM*= variables (environment wins).

* Where permanent delete is still preferable

- You *intend* unrecoverable wipe (secrets, free space forensics)
- Non-Linux platforms (use OS trash APIs, not this crate)
- You must delete *inside* the trash by policy that forbids recoverability

Use =rtrash empty= / =trash-rm= only after accepting permanent loss of those entries.

* Durability and multi-volume (shipped)

- Put fsyncs the reserved =.trashinfo= before the payload move.
- Cross-device (EXDEV) put/restore preserve content, symlink targets, mode, and mtime.
- Each trash root uses an exclusive =flock= on =.rtrash.lock= for put and empty.
- Volume topdir is the longest matching mount point from =/proc/self/mounts= (btrfs multi-subvol safe; not pure =st_dev= parent walk alone).
- Default empty/list/restore/rm scan home trash plus existing trash on every non-pseudo mount (trash-cli multi-volume parity), including =/=.

* Library layout

#+begin_src text
src/lib.rs          public modules + optional python feature
src/main.rs         multi-call CLI dispatcher
src/put.rs          rm-compatible trash put
src/empty.rs        age filter + full wipe path
src/fastdelete.rs   unlinkat tree walk; btrfs subvol destroy
src/drm.rs          optional mpifileutils drm backend for large purges
src/list.rs restore.rs rm.rs trashdir.rs info.rs util.rs
src/python.rs       PyO3 (feature = python)
#+end_src

CLI and Python call the *same* put/empty/list/restore entry points—no second filesystem model.
