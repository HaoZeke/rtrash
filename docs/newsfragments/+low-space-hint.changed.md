The low-space and big-trash warnings of `put` and `status` now point at `rtrash list --sort=size --format='{id} {path}'` and `rtrash rm -i --max-count=1 --match=id ID`, so one listed item is removed after a confirmation. The id is the trash name and its deletion date, and rm checks it again before removing. A repository that still holds risky git work is refused unless `-f` is given. Nested repositories count, a directory that was not fully scanned is unknown, and a git status or stash probe that fails stays unknown even when another probe saw unpushed commits. Unknown stays in the warning when other items are dirty or unpushed. The warning looks at what is in the trash now, not only at what this run moved. On the FreeDesktop trash the undo hint is printed after the move, whose record already holds the batch id. On Windows the hint names `rtrash restore --batch=last` only after the last-put record is written, and otherwise says to restore from the Recycle Bin. On WSL it names `rtrash wsl restore` or Explorer. `rtrash undo` does not restore the Recycle Bin. A dry run does not report git work. The operand keeps its final component, so a symlink or junction is not reported as the directory it points at, and the path in the warning is the path that was moved.
