The low-space and big-trash warnings of `put` and `status` now point at `rtrash list --sort=size` and `rtrash rm -i --max-count=1 --match=exact PATH`, so one listed original path is removed after a confirmation. When a put just moved a repository flagged dirty, unpushed or unknown into a trash, that trash's warning says permanently removing it would lose the work. Dirty work is named even when commits are also unpushed, and a repository git cannot read stays unknown and is never pointed at removal. The undo hint is printed only after the move has succeeded. On Windows the operand keeps its final component, so a symlink is not reported as the directory it points at.
