On Windows a `$I` record that is a Compact file, or another data reparse point, is reopened from the handle already open, without following a path, so a symlink that takes the name is not read. When that reopen is a plain file, the bytes are the file. When the reparse tag cannot be confirmed, or the reopen still shows a reparse tag, the record is unreadable and kept, not read as its reparse buffer. A name surrogate is not read. A record that cannot be read is reported as `unreadable: ... (kept)` and left in place; `--fix` removes a dangling record, or one that was read and cannot be parsed or is larger than any `$I` record. An unreachable `$R` is not dangling.
